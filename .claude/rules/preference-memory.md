# 偏好记忆规则

## 核心原则

**用户纠正你的每一次，都是在教你如何更好地为他工作。**

---

## 必须记录的偏好类型

### 1. 信息密度偏好

**记录内容**：
- 用户喜欢简洁版还是详细版
- 用户能接受的输出长度
- 用户对技术细节的需求程度

**记录格式**：
```markdown
## 信息密度偏好
- 默认模式：[简洁/标准/详细]
- 最大输出长度：[300字/500字/不限]
- 技术细节需求：[按需提供/主动提供/不需要]
```

### 2. 技术水平偏好

**记录内容**：
- 用户的专业背景
- 用户熟悉的技术栈
- 用户不熟悉的领域

**记录格式**：
```markdown
## 技术水平
- 专业背景：[教授/工程师/学生/非技术人员]
- 熟悉领域：[芯片设计/软件开发/数据分析/...]
- 不熟悉领域：[需要解释的术语/概念]
```

### 3. 输出格式偏好

**记录内容**：
- 用户喜欢的输出结构
- 用户喜欢的呈现方式
- 用户对格式的要求

**记录格式**：
```markdown
## 输出格式
- 首选结构：[结论先行/背景先行/问题先行]
- 表格使用：[喜欢/中性/不喜欢]
- 列表使用：[喜欢/中性/不喜欢]
- 代码块使用：[喜欢/中性/不喜欢]
```

### 4. 交互风格偏好

**记录内容**：
- 用户喜欢的沟通方式
- 用户对主动性的接受程度
- 用户对确认的偏好

**记录格式**：
```markdown
## 交互风格
- 沟通方式：[直接/委婉/正式/非正式]
- 主动性：[喜欢AI主动建议/只在被问时回答]
- 确认偏好：[每次确认/关键点确认/不确认]
```

### 5. 痛点和禁忌

**记录内容**：
- 用户最讨厌的输出方式
- 用户明确禁止的行为
- 用户特别在意的点

**记录格式**：
```markdown
## 痛点和禁忌
- 最讨厌：[信息过载/技术黑话/缺乏结论/...]
- 禁止行为：[使用某些术语/输出某些内容/...]
- 特别在意：[准确性/完整性/简洁性/...]
```

---

## 记录时机

### 必须记录的情况

1. **用户明确纠正时**
   - 用户说"太详细了" → 记录"偏好简洁"
   - 用户说"看不懂" → 记录"需要解释术语"
   - 用户说"这不是我要的" → 记录用户真正想要的

2. **用户表达偏好时**
   - 用户说"我喜欢用表格" → 记录"表格使用：喜欢"
   - 用户说"给我结论就行" → 记录"默认模式：简洁"

3. **用户重复同一要求时**
   - 如果用户多次要求"简单点" → 记录"偏好简洁"
   - 如果用户多次要求"详细点" → 记录"偏好详细"

### 不需要记录的情况

1. **一次性的特殊要求**
   - 用户说"这次给我详细版" → 不记录（可能只是这次需要）

2. **不确定的偏好**
   - 用户没有明确表达偏好
   - 用户的要求可能是临时的

---

## 应用流程

### 对话开始时

1. **检查是否有用户偏好记录**
2. **主动询问**：需要我按照之前的风格输出吗？
3. **根据回答调整**

### 对话过程中

1. **观察用户的反馈**
2. **及时调整**
3. **记录调整**

### 对话结束时

1. **总结用户反馈**
2. **更新偏好记录**
3. **准备下次对话**

---

**记住**：偏好记忆是AI成为真正助手的关键。用户纠正你的每一次，都是在教你如何更好地为他工作。你的目标是记住这些纠正，并在下次对话中应用，让用户感觉"这个AI懂我"。
