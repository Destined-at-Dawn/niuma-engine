# R21 -- 三层文件保护铁律（归档 + Git分支隔离 + 每日Zip快照）

> 优先级：最高（与 script-safety-check 同级）
> 创建：2026-07-06
> 适用范围：所有工作区下的所有 AI、Agent、脚本

---

## 背景

2026年7月，生产环境扩展到 5 个工作区、128+ skill、6条定时任务。
单个 .gitignore 和 no-blind-overwrite 已不足以防止事故。

三层保护不是「更安全」，而是「一层失效时另一层能兜底」。

```
L1 操作前归档 ---> 修改/删除任何文件前先复制到归档目录
L2 Git分支隔离 --> 所有AI修改走 agent/{date} 分支，3天自动合并，禁止直推main
L3 每日Zip快照 -> 每天23:59全量打包，7天内全保留，8-30天保留每周一
```

---

## 铁律 1：修改/删除前必须先归档（L1）

触发：任何对已存在文件的修改、覆盖写入、删除操作。

强制流程：
1. 执行归档脚本（将原文件复制到归档目录）
2. 确认输出全部 OK
3. 执行修改/删除操作
4. 验证操作结果

归档位置：各工作区根目录下的 `归档/` 目录
命名格式：{YYYY-MM-DD}-{操作描述}

禁止：修改/删除前不归档。没有「这次改动很小」的例外。

---

## 铁律 2：不准直接 push 到 main（L2）

触发：任何 git commit + push 操作。

强制流程：
1. 确认当前在 agent/{YYYY-MM-DD} 分支（不在 main）
2. git add -A
3. git commit -m "{类型}: {描述} [{日期}] [Agent: {名称}]"
4. git push origin agent/{YYYY-MM-DD}

3天自动合并：分支创建满3天后，定时任务自动合并到 main + 删除远程分支。

禁止：
- [CRITICAL] git push origin main
- [CRITICAL] git push --force 到任何共享分支
- [CRITICAL] 在 main 分支上直接 commit

---

## 铁律 3：每日 zip 快照不可跳过（L3）

自动执行：每天 23:59 由定时任务触发。

保留策略：
- 0-7天：全保留（每天一份）
- 8-30天：保留每周一
- 31-90天：保留每月1日
- 90天以上：归档到长期存储

---

## 跨 Agent 协作铁律

- 不互相覆盖：操作同一文件时，后启动的 Agent 等前一个 commit+push 后再操作
- 身份标注：每个 commit 标注 [Agent: {名称}]
- 冲突预防：修改前先 git fetch && git status，确认无冲突

---

## 违规检测

- [ ] 修改文件后归档目录没有当天的子目录
- [ ] Git log 中出现直接提交到 main 的非 agent/ commit
- [ ] Snapshots 目录连续 2 天没有新 zip
- [ ] git branch -r 中没有当天的 agent/ 分支（当天有修改时）

---

## 认知科学支撑

| 原理 | 来源 | 应用 |
|------|------|------|
| 瑞士奶酪模型 | 安全工程 | 三层各自有漏洞，但漏洞对齐的概率极低 |
| 防御深度 | 军事/安全 | 单层防御不可靠，多层防御才有意义 |
| 损失厌恶 | 思考快与慢 | 保护已有数据比创造新数据更紧迫 |
| 墨菲定律 | 系统思维 | 假设每一层都可能失效 |
