# 知识中枢架构规则（Knowledge Hub Architecture）

> 优先级：高（与 competition-workspace-architecture 同级）
> 创建：2026-07-06
> 核心理念：跨工具、跨工作区的知识不应该靠人工复制粘贴来同步

---

## 核心铁律

知识中枢是所有工作区的单一真相源。工作区文件是中枢的投影，不是独立副本。

---

## 一、知识中枢目录结构

```
知识中枢/
├── 00-注册表/          ← 全局索引层（工作区/Skill/规则注册表）
├── 01-工作区记忆/       ← 各工作区的持久记忆
├── 02-共享规则/         ← 跨工作区通用规则（一改全改）
├── 03-跨区教训/         ← 全局教训库（禁止只写本地不写中枢）
├── 04-SOP/             ← 全局 SOP 库
├── 05-每日记忆/         ← 跨工具每日交接
└── 06-跨区项目/         ← 跨工作区项目上下文卡
```

---

## 二、工作区 <-> 中枢同步协议

### 读取优先级（每个工作区启动时）

| 优先级 | 读取内容 | 路径 |
|--------|---------|------|
| P0 | 工作区自身 CLAUDE.md + rules/ | 工作区本地 |
| P1 | 共享规则最新版本 | 知识中枢/02-共享规则/ |
| P2 | 跨区教训（最近7天） | 知识中枢/03-跨区教训/INDEX.md |
| P3 | 全局 SOP 索引 | 知识中枢/04-SOP/全局SOP索引.md |

### 写入规则（铁律）

| 场景 | 写入位置 | 规则 |
|------|---------|------|
| 修改共享规则 | 先改中枢 -> 再同步到各工作区 | 中枢是权威源 |
| 新增跨区教训 | 同时写入 03-跨区教训/ + 本地 memory | 双写协议 |
| 每日记忆 | 05-每日记忆/ + 工作区本地 memory/ | 中枢存结构化版 |
| 项目决策 | 工作区本地 memory/long-term.md | 项目级不污染中枢 |

---

## 三、li-zhongshu 守护者机制

li-zhongshu 是跨工具全局治理的自动化执行体：

Rule 1: 教训双写（核心铁律）
- 任何跨工具参考价值的教训必须同时写入本地 + 知识中枢
- 禁止「只写本地不写中枢」

Rule 2: 无 SOP 先查中枢
- 启动无对应 SOP 的任务时，必须先扫描 03-跨区教训/ 和 04-SOP/

Rule 3: 会话启动感知
- 每次对话启动，读取 03-跨区教训/INDEX.md 最近7天条目

---

## 四、共享规则的「一改全改」机制

- 修改中枢/02-共享规则/ 下任何文件
- li-sync 自动识别变更并同步到所有含该规则副本的工作区
- 禁止手动逐个工作区改

---

## 五、文件夹运作逻辑（跨工作区统一）

每个工作区标准目录：
- outputs/：产出文件
- memory/：分级记忆（long-term.md + {日期}.md）
- projects/proj-xxx/：临时项目（只放 task.json + project.md）
- .claude/rules/：规则（Claude Code 自动加载）
- CLAUDE.md：工作区入口
- 归档/：双归档备份目录

铁律：
- R16 根目录优先：记忆->memory/，产出->outputs/
- 禁止 rules/：规则唯一位置 .claude/rules/
- proj-xxx 最小化：只保留 task.json + project.md
